# План разработки YetAnotherOneCLauncher

Этап 1 (чтение списков баз) уже сделан. План начинается с этапа, который убирает накопившиеся хвосты, потом идёт минимальная рабочая версия (MVP), затем расширения. Этапы расставлены так, чтобы после каждого получалось приложение, которым можно пользоваться. Для каждого этапа указано, что входит в работу и когда он считается готовым.

## Этап 2. Платформы и запуск баз: ядро MVP (1–1,5 недели) — сделан для Windows

**Статус.** Поиск платформ, выбор версии, командная строка и запуск работают и проверены на реальной машине:
найдено 7 платформ (x64 и x86), 1С правильно разбирает собранную командную строку (проверено через `CREATEINFOBASE`
и запуск тонкого клиента), тестов 145. Осталось:

- [ ] проверить на Linux: пути `/opt/1cv8`, заголовки ELF, запуск через `ArgumentList` и `xdg-open`;
- [ ] старая раскладка Linux `/opt/1C/v8.3/<arch>`: в пути нет версии, нужно выяснить, откуда её брать;
- [ ] история запусков — перенесена на этап 3, где появится хранилище настроек.

Отличия от первоначального плана:

- если нужной версии нет, предлагается ближайшая из той же ветки (для 8.3.24.1467 — сначала 8.3.24.x, затем 8.3.x.x),
  а не самая новая вообще: переход на другую ветку (8.3 → 8.5) может потребовать конвертации базы;
- в Windows командная строка собирается по правилам 1С (кавычки удваиваются), а не через `ArgumentList`:
  его экранирование `\"` 1С не понимает.

### 2.1. Поиск установленных платформ

- **Модель.** `PlatformVersion` для версий вида `8.3.24.1548`: разбор, сравнение, проверка по маске `8.3`, `8.3.24`, `8.3.24.1548`. `PlatformInstallation` хранит версию, разрядность (x86 или x64), каталог `bin` и список доступных программ: `1cv8` (толстый клиент и Конфигуратор) и `1cv8c` (тонкий клиент).
- **Windows.** Каталоги из `InstalledLocation` в `1cestart.cfg` и `DefaultPlatformInstallRoots`, внутри них подкаталоги `<версия>\bin\1cv8.exe` и `1cv8c.exe`.
- **Linux.** Каталоги `/opt/1cv8/<arch>/<версия>/` и старый вариант `/opt/1C/v8.3/<arch>/`. Пути нужно сверить на реальных установках.
- **Интерфейс.** `IPlatformLocator` в Platform, модель и логика выбора в Core.
- **Выбор версии для базы.**
  1. Ключ `Version` базы как маска.
  2. Если его нет, `DefaultVersion` из cfg.
  3. Если нет и его, самая новая установленная версия.

  При равных версиях предпочитается x64, но это можно переопределить в настройках.
- **Тесты.** Логика выбора проверяется на искусственной файловой системе: интерфейс `IFileSystem` или временные каталоги.

### 2.2. Построение командной строки

Чистая функция в Core: `LaunchRequest` → `LaunchCommand`, то есть путь к exe и список аргументов.

- **Режим.** `ENTERPRISE` или `DESIGNER`. Конфигуратор всегда запускается через `1cv8`, тонкий клиент только в режиме Предприятия.
- **Клиент.** Из ключа `App`: `ThinClient` → `1cv8c`, `ThickClient` → `1cv8`, `WebClient` → открыть URL в браузере. `Auto` → `1cv8c` для серверных и веб-баз, для файловых по настройке.
- **Подключение.** `/F "<путь>"`, `/S "<сервер>\<база>"` или `/WS "<url>"`. Для нестандартных строк подключения запасной вариант `/IBConnectionString`.
- **Остальные параметры:**
  - `/WA+` или `/WA-` из ключа `WA`;
  - `/O Low` или `Normal` из `ClientConnectionSpeed`;
  - `/N` и `/P` для пользователя и пароля (см. этап 5);
  - `AdditionalParameters` дописываются в конец без изменений.
- **Кавычки.** Значение с пробелами или кавычками берётся в кавычки, кавычка внутри удваивается (правила 1С). В Windows строка собирается по этим правилам, в Linux аргументы передаются через `ProcessStartInfo.ArgumentList`.
- **Тесты.** Отдельный тест на каждое сочетание вида подключения, клиента и режима.

### 2.3. Запуск процесса

- `IProcessLauncher` в Platform: процесс запускается отдельно от лаунчера, запускать через оболочку не нужно. На Linux задаётся рабочий каталог и переменные окружения, если платформе это нужно.
- Понятные ошибки: «платформа 8.3.22 не установлена, есть 8.3.24 — запустить на ней?», «файл базы не найден».
- ~~После успешного запуска база записывается в историю.~~ Перенесено на этап 3.

**Готово, когда** из временного окна любую базу можно открыть двойным щелчком в Предприятии, а через меню в Конфигураторе, на Windows и на Linux.

## Этап 3. Главное окно на MVVM (2 недели)

### 3.1. Архитектура UI

- `CommunityToolkit.Mvvm`: `ObservableObject` и `RelayCommand`. Привязки только компилируемые.
- ViewModel-и: `MainWindowViewModel`, `CatalogTreeViewModel`, `InfoBaseViewModel`, `FolderViewModel`, `DetailsPanelViewModel`.
- Весь код из `MainWindow.axaml.cs` переезжает в ViewModel-и, в code-behind ничего не остаётся.
- Тесты ViewModel-ей как обычные юнит-тесты, тесты представлений через `Avalonia.Headless.XUnit`.

### 3.2. Хранение настроек лаунчера

- JSON в `AppDataDirectory` через генератор кода `System.Text.Json`, чтобы работало с AOT. Запись атомарная через `AtomicFileWriter`.
- Что хранится: избранное, история (время и режим запуска), выбранная версия платформы для базы, тема, размеры окна, режим отображения.
- Все записи привязаны к `InfoBase.IdentityKey`. Если у базы пропал `ID`, запись переносится по строке подключения.

### 3.3. Возможности окна

- **Отображение.** Дерево папок или плоский список, переключается одной кнопкой.
- **Быстрый поиск.**
  - Фокус в поле поиска сразу при открытии окна.
  - Ищет по имени, пути, серверу и имени базы на сервере.
  - Исправляет раскладку ЙЦУКЕН ↔ QWERTY: `,e[` находит «бух».
  - Находит по начальным буквам слов: «ЗУП» находит «Зарплата и управление персоналом».
  - Подсвечивает совпадения. Порядок результатов: совпадение в начале имени, затем избранное, затем часто открываемые.
- **Избранное** закреплено сверху. **Недавние**: последние N баз.
- **Панель подробностей:** строка подключения, версия, клиент, источник записи (личный или общий список), последний запуск, размер кэша.
- **Клавиатура:**
  - Enter — Предприятие;
  - Ctrl+Enter — Конфигуратор;
  - Ctrl+F — поиск;
  - Esc — очистить поиск;
  - F2 — изменить;
  - Del — удалить.
- **Контекстное меню** базы: запуск в режимах, копировать строку подключения, открыть каталог базы или кэша.
- **После запуска** окно сворачивается или закрывается, это настраивается.
- **Прочее.** Сохраняются тема, положение окна и раскрытые папки. Значок в трее пока не делаем, это на будущее.

**Готово, когда** лаунчер полностью заменяет штатный стартер для ежедневного запуска баз. **Это MVP и первый выпуск 0.1.**

## Этап 4. Редактирование личного списка (1,5 недели)

- **Операции в Core:** добавить, изменить, удалить базу; создать, переименовать, удалить папку; переместить запись между папками; изменить порядок (`OrderInTree` и `OrderInList`). Все операции работают через `V8iSection`.
- **Новые записи.** `ID` — новый GUID. Порядок ключей такой же, как пишет штатный стартер.
- **Защита от одновременной записи:**
  - перед сохранением сравнить время изменения и хэш файла с тем, что было при чтении;
  - если файл изменился, перечитать его и повторить операцию. Если повторить нельзя, показать пользователю конфликт;
  - перед первой записью за сеанс сделать резервную копию `ibases.v8i.bak`.
- **Устаревшая строка подключения.** `InfoBase.Connection` разбирается один раз при создании объекта; после изменения `Connect` объект нужно пересоздавать или пересчитывать.
- **Диалоги.**
  - Мастер добавления базы: вид подключения (файл, сервер или веб), проверка полей, выбор каталога.
  - Редактор всех ключей, включая неизвестные, в расширенном режиме.
- **Перетаскивание** баз и папок в дереве.
- **Общие списки.** Их записи только для чтения, но базу можно скопировать в личный список.
- **Обмен списками.** Импорт и экспорт `.v8i`, выбранных баз или папки целиком.
- **Отслеживание файлов.** `FileSystemWatcher` на `ibases.v8i` и `1cestart.cfg`: если их изменила программа снаружи, список обновляется сам.

**Готово, когда** после любых правок штатный стартер 1С открывает список без ошибок и без потерь. Это проверяется интеграционными тестами на реальных образцах.

## Этап 5. Параметры запуска и учётные данные (1 неделя)

- **Библиотека параметров.** Набор готовых шаблонов с описаниями:
  - `/DisableStartupMessages` и `/DisableStartupDialogs`;
  - `/RunModeOrdinaryApplication` и `/RunModeManagedApplication`;
  - `/UC <код>`, `/C <строка>`, `/Execute <epf>`;
  - `/L`, `/VL`, `/UseHwLicenses±`, `/ClearCache`.

  Пользователь может добавлять свои шаблоны.
- **Где применяются.** У базы или у папки (папка передаёт параметры вложенным базам), либо разово при запуске через «Запустить с параметрами…».
- **Порядок применения:** `AdditionalParameters` из v8i, затем параметры папки, затем параметры базы, затем разовые.
- **Хранение паролей.** Нужен `ICredentialStore`:
  - Windows — Credential Manager или DPAPI;
  - Linux — libsecret через `secret-tool` или D-Bus, а если его нет, отказ с понятным сообщением.

  Пароли не хранятся ни в JSON, ни в v8i и не пишутся в лог. В логе показывается командная строка с `/P ***`.

## Этап 6. Очистка кэша баз (3–4 дня)

- Найти каталоги кэша по `ID` базы во всех `InfoBaseCacheRoots` и посчитать их размер.
- Показать размер кэша у каждой базы и общий объём. Отдельно показать кэш без хозяина, то есть с `ID`, которых больше нет ни в одном списке.
- Перед удалением проверить, не открыта ли база: есть ли процессы 1С и заняты ли файлы кэша. Если открыта, предупредить.
- Удаление в корзину через `IRecycleBin`: на Windows `SHFileOperation` или `IFileOperation`, на Linux корзина по стандарту freedesktop в `~/.local/share/Trash`. Можно выбрать и окончательное удаление.
- Действия «Очистить кэш и запустить» и массовая очистка.

## Этап 7. Сетевые источники и надёжность (1 неделя)

- **Веб-сервис списков (`InternetService`).** Реализовать клиент к сервису 1С `WebCommonInfoBases` (SOAP, методы проверки и получения списка по `ClientID`). Протокол уточнить по документации 1С и снять реальный трафик.
- **Кэш общих списков.** Последнюю успешно прочитанную копию каждого общего списка и списка с веб-сервиса сохранять в `AppDataDirectory`. Если источник недоступен, показывать базы из кэша с пометкой «данные на <дату>».
- **Фоновая проверка доступности** (с отключением в настройках): существует ли каталог файловой базы, отвечает ли сервер по порту 1541 на TCP.
- **Загрузка.** Сначала сразу показать личный список и кэш, затем постепенно добавлять общие списки по мере их чтения.

## Этап 8. Упаковка, обновления, выпуск (1–1,5 недели)

- **Сборка.** `dotnet publish` в один самодостаточный файл. Проверить, работает ли NativeAOT или обрезка кода (trimming) с Avalonia. Если нет, остаётся самодостаточная сборка с ReadyToRun.
- **Windows.** Установщик через Velopack. Дополнительно portable-вариант в zip, который хранит настройки рядом с exe. Подпись кода, если будет сертификат.
- **Linux.** AppImage, по возможности deb и rpm. Файл `.desktop`, значок, регистрация как обработчика `.v8i`.
- **Автообновление** через Velopack: канал релизов в GitHub или GitLab Releases, проверка при старте, обновление по согласию пользователя.
- **Сопоставление файлов.** Открытие `.v8i` двойным щелчком показывает содержимое и предлагает импорт.
- **Выпуск.** CI собирает артефакты по тегу, журнал изменений ведётся в `CHANGELOG.md`.

**Готово, когда** выпуск 1.0 ставится и сам обновляется на Windows 10/11 и Ubuntu или Astra Linux.

## Работа на всех этапах

- **Тесты.** В Core покрыта вся логика: разбор, командная строка, выбор версии, поиск, операции со списком. Для UI — тесты ViewModel-ей и headless-тесты.
- **Логи и диагностика.** Лог в файл с ротацией. Кнопка «Собрать диагностику» упаковывает лог и обезличенный список в zip.
- **Локализация.** Основной язык русский. Строки сразу выносить в ресурсы, чтобы позже добавить английский.
- **Доступность.** Все действия доступны с клавиатуры, у элементов есть подписи для экранных дикторов.
- **Документация.** README для пользователя и `docs/ARCHITECTURE.md` для разработчика.
- **macOS.** Пока не поддерживается, но Platform заранее проектируется так, чтобы добавить `MacPlatformPaths` без изменений в Core.
