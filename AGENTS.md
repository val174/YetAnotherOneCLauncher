# YetAnotherOneCLauncher

Альтернативное приложение для запуска информационных баз 1С:Предприятие 8.
Работает на Windows и Linux. Стек: .NET 10 и Avalonia 12.

## Состояние

Сделаны этапы 0–7 (правки личного списка проверены штатным стартером): ядро чтения списков, поиск платформ и запуск (Windows), главное окно с поиском, избранным и историей, редактирование личного списка, параметры запуска и сохранённые пароли, очистка кэша баз, веб-сервис и копии общих списков, проверка доступности баз. Следующий — этап 8, упаковка и выпуск. Подробности — в [docs/ROADMAP.md](docs/ROADMAP.md).

## Сборка и запуск

Нужен .NET SDK 10.

```powershell
dotnet build
dotnet test
dotnet run --project src/YetAnotherOneCLauncher.App
```

Один исполняемый файл без установленного .NET (профили в `src/YetAnotherOneCLauncher.App/Properties/PublishProfiles`):

```powershell
dotnet publish src/YetAnotherOneCLauncher.App -p:PublishProfile=win-x64    # artifacts/publish/win-x64/YetAnotherOneCLauncher.exe
dotnet publish src/YetAnotherOneCLauncher.App -p:PublishProfile=win-x64-compact  # artifacts/publish/win-x64-compact/YetAnotherOneCLauncher.exe — компактный, ~63 МБ
powershell -File scripts/publish-win.ps1                             # оба варианта для Windows
dotnet publish src/YetAnotherOneCLauncher.App -p:PublishProfile=linux-x64  # artifacts/publish/linux-x64/YetAnotherOneCLauncher
```

Файл около 144 МБ: внутри .NET, библиотеки отрисовки и заранее скомпилированный код (`PublishReadyToRun`, без сжатия — ради скорости открытия: окно через ~0,9 с вместо ~2,1 с при файле ~48 МБ). Библиотеки отрисовки лаунчер при первом запуске распаковывает в `%TEMP%\.net\YetAnotherOneCLauncher` (Linux: `~/.net`), поэтому первый старт новой версии дольше (~3–4 с). Настройки и логи — в каталоге настроек пользователя, не рядом с файлом. Время открытия пишется в лог: «Окно открыто через …», «Список баз показан через …», «Платформы найдены …».

Предупреждения компилятора и анализаторов считаются ошибками (`TreatWarningsAsErrors`, `AnalysisLevel=latest-recommended`).
CI (GitHub Actions, `.github/workflows/ci.yml`) собирает решение и запускает тесты на Windows и Linux.

Лог приложения: `<каталог настроек>/logs/launcher-<дата>.log`, то есть `%APPDATA%\YetAnotherOneCLauncher\logs` в Windows и `~/.config/YetAnotherOneCLauncher/logs` в Linux. В отладочной сборке пишутся и сообщения уровня Debug.

Правило: **Core ничего не знает об ОС и UI**. Пути 1С передаются в ядро из `Platform`. Из инфраструктуры Core зависит только от `Microsoft.Extensions.Logging.Abstractions`; классы Core работают и без логгера.

## Принятые решения

- **Записи хранят исходную секцию файла.** Свойства `InfoBase` читаются из `V8iSection`, изменения пишутся в неё же. Так при сохранении не теряются неизвестные ключи, а неизменённые строки остаются байт в байт.
- **Запись файлов атомарная.** Сначала пишется временный файл рядом, затем он заменяет оригинал. Можно сохранить резервную копию.
- **Дубликаты** определяются по `ID`, а если его нет, то по нормализованной строке подключения. Побеждает первая запись: сначала личный список, затем общие в порядке следования в cfg.
- **Секция без `Connect`** считается папкой. Папки, которые есть только в путях `Folder` у баз, создаются в дереве автоматически.
- **Отсутствующий личный список** считается пустым. Он будет создан при первом добавлении базы.
- **Недоступный общий список** (сеть, права, таймаут 5 с) не прерывает загрузку и не задерживает ни окно, ни запуск баз: личный список показывается сразу, общие — по мере чтения, платформы ищутся параллельно (`CatalogLoad`) и применяются, как только найдены. Первая загрузка начинается в `Program` до создания окна (`StartupCatalog`). Если источник недоступен, базы берутся из последней удачной копии (`<каталог настроек>/list-cache`) с пометкой даты.

- **Платформа ищется по каталогам с именем-версией** (`8.3.24.1548`) не глубже двух уровней от корня, с `1cv8`/`1cv8c` в `bin` или прямо в каталоге. Так подходят раскладки Windows и Linux. Разрядность берётся из заголовка исполняемого файла, а не из пути.
- **Выбор версии:** маска `Version` базы, иначе `DefaultVersion` стартера, иначе самая новая; при равных версиях — x64. Если маски нет среди установленных, лаунчер не запускает молча другую версию, а спрашивает, предлагая ближайшую из той же ветки.
- **Клиент:** Конфигуратор — всегда `1cv8`; `App=Auto` — тонкий клиент, а если его нет в подходящей версии — толстый; явный `ThinClient` на толстый не заменяется.
- **Командная строка в Windows** собирается по правилам 1С: кавычки внутри значения удваиваются. Экранирование .NET (`\"`) 1С не понимает. `AdditionalParameters` дописываются как есть, как у штатного стартера. Пароль в логах и на экране скрыт.
- **Запуск не блокирует лаунчер:** процесс платформы запускается отдельно, его завершения не ждём.
- **Настройки лаунчера — отдельно от файлов 1С**, в `<каталог настроек>/settings.json`: избранное, история, выбранная версия платформы, вид окна. Списки баз лаунчер ради этого не меняет. Записи хранят и `ID` базы, и строку подключения: если `ID` пропадёт, запись найдётся по подключению. Повреждённый файл откладывается в `settings.json.bad`, лаунчер стартует с настройками по умолчанию.
- **Поиск:** все слова запроса должны найтись; порядок — по точности совпадения (начало имени, начало слова, начальные буквы, подстрока, затем прочие поля), избранное и частота запусков только уточняют порядок внутри одного уровня точности.
- **Общие списки, списки с веб-сервиса и `1cestart.cfg` только читаются.** Список баз пишется в одном месте — `PersonalListStore`, и только в личный `ibases.v8i` (путь задаётся при запуске). Базы и папки из общих списков — «только чтение» (`ListSource.IsReadOnly`): изменить можно лишь их копию в личном списке. «Сохранить ссылку в файл» отказывается писать поверх общего списка. Копии общих списков — в `<каталог настроек>/list-cache`. Проверяет тест `Common_list_file_is_never_changed`.
- **Правка личного списка не теряет чужих изменений.** Каждая правка применяется к заново прочитанному `ibases.v8i`; запись ищется по `ID` (без него — по подключению и имени). Если нужную запись изменили после загрузки — конфликт: лаунчер сообщает и перечитывает список. Перед записью файл сверяется ещё раз; если его успели изменить, правка повторяется. Первая запись за сеанс сохраняет прежнюю версию в `ibases.v8i.bak`.
- **Новые записи — как у штатного стартера:** те же ключи в том же порядке, `ID` — новый GUID, порядок — с шагом 16384. Меняются только затронутые строки.
- **Параметры запуска** применяются по порядку: `AdditionalParameters` из списка, параметры папок (от верхней к вложенной), параметры базы, разовые. Хранятся в настройках лаунчера, список баз не меняется.
- **Пароли — только в хранилище ОС.** В `settings.json` лежит ключ записи, в логе и на экране — `/P ***`. Если пароль не прочитался, база всё равно запускается, и 1С спрашивает пароль сама.
- **Кэш удаляется только целыми каталогами баз** (имя — GUID); служебные каталоги платформы не трогаются. Каталог, файлы которого открыты, пропускается целиком, а не удаляется наполовину. Удаление — насовсем, без корзины; по умолчанию только кэш, без локальных настроек пользователя (Roaming).
- **ViewModel не зависят от Avalonia:** окна, диалоги, буфер обмена и тема — за интерфейсами, поэтому логика окна проверяется обычными тестами, а разметка и клавиатура — headless-тестами.

## Образцы файлов для тестов

`tests/YetAnotherOneCLauncher.Core.Tests/Fixtures/` содержит синтетические образцы. Настоящие файлы с рабочих машин (`ibases.v8i`, `1cestart.cfg`) полезно добавить туда же, предварительно обезличив имена серверов и баз. Для каждого стоит добавить тест, что файл читается и записывается обратно без изменений (как `Round_trip_of_real_sample_is_byte_exact`).
